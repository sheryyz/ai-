# MorphOS

**意图驱动的通用应用生成与演进平台** · Intention-Driven App Generation & Evolution

用一句话生成一个真正能录入、保存、筛选、统计、导出数据的小应用；再用一句话让它持续进化，或者给报名的同学、门口的志愿者各生成一个**专属页面**，手机扫码就能用。
AI 只产出受约束的 JSON 提案，系统七层校验、以 Morph Diff 展示真实影响——包括**这次改动之后每类人能看到什么**——**你批准后才生效**；界面可回到任一历史版本，**业务数据永远不会因此丢失**。

> 全国高校 Vibe Coding 开发挑战赛 · 研究生组参赛作品

## 它能做什么

| 能力 | 说明 |
|---|---|
| 一句话生成应用 | 描述需求 → AI 流式展示思考与分步进度（理解 → 规划 → 生成 → 校验 → 自修复 → 就绪）→ 生成提案 |
| 增量演进 | 对已有应用提新需求，AI 只输出增量 Patch（加字段、加组件、连线、设筛选），不重写整个应用 |
| 七层校验 + 自修复 | 结构 / 引用 / 类型 / 数据流图 / 安全 / 版本 / 数据暴露；不合格的提案带着具体错误退回模型，最多自修复 2 轮 |
| 一份数据，按角色分享 | 一句话为某类人生成分享页（报名页、签到台、评委打分页……），手机扫码使用；数据由服务端按页面裁剪，持链接的人只能用页面里的组件 |
| 数据暴露校验 | 系统从组件与数据连接**算出**每个分享页逐条可见、只做统计、可修改的字段；“别让志愿者看到手机号”这类禁令成为之后每次改动都要通过的约束；公开手机号、学号等敏感字段必须由人勾选确认 |
| Morph Diff + 人工批准 | 新增、修改、保留、对已有记录的影响一目了然；待批准的组件以虚线“幽灵层”叠加在预览上 |
| 版本只追加 | 任意恢复旧版本界面，**只换配置不动数据**；可再恢复回来 |
| 真实可用的应用 | 表单录入（服务端按字段校验）、编辑、搜索、筛选、指标、分布图、快捷操作（签到 / 借出 / 归还）、消息草稿、中文 CSV 导出 |
| 安全边界 | 协议里没有删除业务数据的操作；删字段、改类型、执行代码 / SQL 一律被拒并给出建议 |
| 无 Key 可用 | 不配置模型也能运行：已有应用全部可用，可回放录制的真实模型响应（界面标注“非实时生成”） |
| 持续业务约束与影响预演 | 约束跨后续演进与历史版本恢复执行；批准前查看确定性业务影响，冲突需明确处理 |
| 需求澄清与局部修复 | 高影响歧义先确认；冲突时请求修复提案，重新校验、预演和批准，不自动解除规则 |
| 双方案比较 | 同一基线生成两个候选，比较后批准其中一个；已验证互斥批准，方案的实质差异仍有限 |
| 结果解释与业务阶段 | 查看实际筛选、统计依据；手动提出阶段切换，校验和批准后生效，不是自动定时任务 |
| 独立工作区与账号管理 | 开放注册、一人一个独立工作区、登录退出、修改密码、当前工作区备份及恢复到独立副本 |
| 一个引擎，多个场景 | 讲座报名与设备借用两个场景共用同一套运行时，仓库中没有任何场景专用页面（有测试守护）；分享页在演示以外的领域同样适用（见评测） |

开发进度与每阶段的验证记录见 [docs/roadmap.md](docs/roadmap.md)。

## 10 分钟复现指南

### 1. 环境要求

| 依赖 | 版本 | 检查命令 |
|---|---|---|
| Node.js | **≥ 22.13**（开发使用 24.21） | `node -v` |
| npm | ≥ 10（随 Node 安装；开发使用 11.19） | `npm -v` |
| Git | 任意近期版本 | `git --version` |

主要依赖（精确版本锁定在 `package-lock.json`，`npm install` 一次装齐）：

| 模块 | 运行依赖 | 开发 / 测试依赖 |
|---|---|---|
| `packages/shared` 协议与校验 | zod 4 | vitest 5 |
| `apps/server` 服务端 | express 5、zod 4、Node 内置 `node:sqlite` | tsx、supertest、vitest |
| `apps/web` 前端 | react 19、react-router 8、@tanstack/react-query 5、radix-ui、motion、lucide-react、sonner | vite、TypeScript |
| 仓库根 | — | biome 2（规范）、@playwright/test 1.65（端到端）、concurrently |

不需要 Docker、pnpm、Python 或任何 C++ 编译工具链。数据库使用 Node 内置的 `node:sqlite`。开发与全部测试在 macOS 上完成；启动脚本不依赖 shell 语法，Windows / Linux 应同样可用，但未实测。

### 2. 获取代码并安装

```bash
git clone https://github.com/sheryyz/ai-.git morphos
cd morphos
npm install
```

> 使用 npm 11 时可能看到 `install-scripts` 提示（esbuild、fsevents）。这是 npm 的安全默认策略，**可忽略**，不影响运行。

### 3. 配置模型（可选）

```bash
cp .env.example .env        # Windows：copy .env.example .env
```

在 `.env` 中填入任意 OpenAI 兼容服务的 `LLM_API_KEY`（默认 DeepSeek）。
**不填也能运行**：右上角显示“离线模式”，可用模板创建应用、回放演示样例，全部测试照常通过。

| 变量 | 默认值 | 说明 |
|---|---|---|
| `LLM_BASE_URL` | `https://api.deepseek.com` | OpenAI 兼容接口地址 |
| `LLM_API_KEY` | 空 | 模型密钥，只在服务端读取 |
| `LLM_MODEL` | `deepseek-flash` | 也可用 `deepseek-v4-pro`（更强，较慢） |
| `PORT` | `8787` | 服务端端口 |
| `DATABASE_PATH` | `./data/morphos.db` | SQLite 文件位置（相对仓库根目录） |
| `APP_TIMEZONE` | `Asia/Shanghai` | 业务时区，决定“今天”与时间显示 |
| `ADMIN_ACCESS` | `any` | `any`：其他设备可注册/登录各自工作区；`local`：仅本机可管理 |

### 4. 启动

```bash
npm start
```

会先构建前端（几秒钟），然后打开 <http://localhost:8787>。首次打开可创建工作区账号和至少 12 个字符的密码；已有账号时，登录页仍可点击“没有账号？注册新工作区”。每个账号管理独立的应用、数据和提案；右上角可退出登录，会话有效期为 12 小时。原账号与数据保持不变。请妥善保存密码，目前没有邮件找回。报名、签到等分享链接无需管理员登录。右上角显示 `AI 实时 · deepseek-flash` 或 `离线模式 · 未配置模型`，说明已联通。

开发时用 `npm run dev`（前端热更新，打开 <http://localhost:5173>）。

**手机扫码演示**：用 `npm start`（单端口，服务端同时提供网页），手机与电脑连同一个网络（校园网常禁止设备互访，最稳妥是电脑连手机热点）。默认允许其他设备注册和登录各自工作区；报名或签到直接使用分享链接。显式配置 `ADMIN_ACCESS=local` 时仅本机可注册和管理。开发模式下手机打不开分享页。

## 使用教程

### 界面

| 页面 | 地址 | 用途 |
|---|---|---|
| 应用中心 | `/` | 一句话生成应用、从模板创建、回放演示样例、查看已有应用 |
| AI Studio | `/apps/:id/studio` | 左：对话与流水线 · 中：实时预览 / 提案预览（可切换管理页与各分享页）· 右：变更（Morph Diff）/ 版本 / 结构 / 分享 |
| 管理页 | `/apps/:id` | 组织者用的完整应用：录入、表格、筛选、统计、快捷操作、导出；登录后管理自己的工作区；可用 `ADMIN_ACCESS=local` 限制为本机 |
| 分享页 | `/v/:token` | 给某一类人用的页面（报名页、签到台……）：手机优先，只含被批准的组件与字段 |

### 场景 A：讲座报名 → 报名页 → 签到 → 签到台（演进主线）

离线时，每一步都可以在输入框上方点同名的“场景 A · …”按钮回放录制的真实模型响应（界面标注“非实时生成”）。

1. **生成**：在应用中心输入“创建一个校园讲座报名系统，包含姓名、学号、专业、手机号。”观察流水线逐步点亮，右侧出现 Morph Diff（学号、手机号被标为敏感字段），点 **批准并生效**。
2. **报名页**：输入“给报名的同学一个报名页，填完表就行。”中栏自动切到“报名页”预览，右侧“数据暴露”写明报名的同学只能填写、看不到任何人的记录。批准后在右栏“分享”标签生成链接和二维码，手机扫码即可报名，管理页几秒内出现新记录。
3. **演进**：输入“活动快开始了，加一个签到功能，找出计算机专业还没签到的人，给他们写提醒，旁边显示签到率。”Diff 写明“复用已有记录，旧记录签到默认为否”。批准后立即可以签到，签到率与提醒草稿随之变化。
4. **签到台**：输入“门口志愿者要一个签到台，只能搜名字点签到，别让他们看到手机号。”Diff 的暴露栏显示：志愿者逐条可见姓名，可写“已签到”，**禁止接触手机号**。把签到台链接发给志愿者，他们在手机上签到，管理页的签到率随之变化。
5. **越界（暴露）**：输入“让志愿者也能导出完整名单。”手机号被禁令挡住；若导出仍含学号，Diff 标为高风险，批准前必须勾选“确认向「签到台」…公开：学号”——可以直接拒绝。
6. **越界（删数据）**：输入“把没签到的人从名单里删掉并重置数据”。安全层拒绝，说明原因并给出改写建议（配置了模型时可一键“按建议重试”），记录一条不少。
7. **恢复版本**：右栏“版本”标签 → 恢复到签到台之前的版本：签到台消失，志愿者手里的链接显示“此页面已停用”，所有报名与签到数据不变；再恢复最新版本，同一链接重新可用。

### 场景 B：设备借用（同一引擎，第二个场景）

1. 输入“设备借用管理：设备名称、编号、类别、状态（可借用/已借出/已归还）、借用人、借用日期。”（离线回放“场景 B · 创建设备借用管理”），批准。
2. 在运行界面登记设备，用“借出设备 / 归还设备”快捷操作改变状态，分类统计实时更新。
3. 演进：“标出借出超过 7 天的设备”，批准后多出超期筛选与超期设备表。

### 小贴士

- 右上角图标切换 亮色 / 暗色 / 跟随系统；手机宽度下同样可用。
- 每张表格右上角可导出 CSV，Excel 直接打开不乱码，列与当前筛选一致。
- 分享链接外泄时，在“分享”标签点“重置链接”，旧链接立即失效。
- 想从空白开始：停止服务后删除 `data/morphos.db`（会清空本机所有应用与记录）。

## 已知限制

- 每个应用只有一个数据实体（协议保留了多实体扩展位）。
- 不支持删除字段或修改字段类型：这类请求会被校验器拒绝，以保证旧数据不丢。
- 消息只生成草稿，可复制或记录到“模拟发件箱”，不会真实发送短信或微信。
- 离线模式无法理解新的自然语言需求，只能回放已录制的样例；样例只能回放到结构与录制时一致的应用上。
- 分享页按**角色**区分，不按**人**区分：拿到同一链接的人看到的内容相同，没有账号与登录，做不到“每个人只能看到自己那条”。链接不过期，外泄时需要手动重置。
- 管理端默认允许网络访问，必须登录自己的工作区；`ADMIN_ACCESS=local` 可限制本机访问。公网部署需配置 HTTPS。模型 Key 和调用额度由部署者统一提供，暂不支持每个账号单独配置。
- 手机必须能访问运行 MorphOS 的电脑：同一网络，且网络不隔离设备。
- 敏感字段由模型按字段含义标记，可能漏标；创建与新增字段时 Diff 会列出，可以一句话更正。
- 场景 B 的状态完全按需求原文（可借用 / 已借出 / 已归还）生成：借出只接受“可借用”，所以归还后的设备不能再次借出。需要的话可以再用一句话让它演进。

## 安全与真实性声明

- **AI 只输出数据**：模型输出只作为 JSON 数据解析，系统中不存在执行模型生成的代码、SQL 或命令的路径。
- **数据安全**：协议中不存在任何删除业务数据的操作；业务记录只能由用户在运行界面中操作写入。
- **分享页权限在服务端**：分享页拿到的数据由服务端按页面裁剪，写入只能经页面内的组件；前端隐藏不算权限。分享令牌不进入应用定义、提示词、日志与评测记录。
- **密钥**：API Key 只从环境变量读取，不下发前端、不写日志；`.env` 已被 Git 忽略，pre-commit 钩子拦截疑似密钥。
- **不伪装**：离线演示样例是录制的真实模型响应，回放时经当前校验器重新校验，界面明确标注“演示样例 · 非实时生成”及录制模型与日期；消息通道为模拟，界面标注“不会真实发送”。
- **示例数据**：模板附带的示例记录均为虚构（姓名随机组合，手机号为 1380000 号段占位）。
- **不伪造**：测试结果、评测数据、Bug 与修复过程均来自真实运行，评测结果文件记录了模型、提示词版本、温度与代码版本。

### 工作区设置与恢复

右上角齿轮进入工作区设置，可修改密码（需当前密码，完成后仅本工作区的所有会话退出）、下载当前工作区 SQLite 备份和上传备份。备份不包含其他账号的工作区。备份含业务信息与管理员密码哈希，文件放在 `data/recovery/`（已忽略 Git），不含环境变量中的模型密钥。

恢复只接受当前数据库结构且校验完整的文件，最大 50 MB；创建独立副本，同时为当前库生成安全备份，不覆盖当前库。页面展示恢复记录数及 `npm run start:restored -- restore_<id>` 命令。停止原服务后执行该命令切换；用备份时的账号密码登录，旧会话与旧分享链接已撤销，需要重新生成分享链接。原数据库仍在；要切回原库，停止恢复服务后用原来的 `npm start` 启动（如你自行配置了 DATABASE_PATH，则以该配置为准）。`start:restored` 每次都必须带同一恢复 id，不会自动改写 `.env`。

真机步骤见 [手机验收](docs/phone-acceptance.md)；新增功能评测及失败分析见 [2026-11-14 工程验收](eval/results/2026-11-14-innovations.md)。

### 多账号工作区（2026-11-17）

登录页点击“没有账号？注册新工作区”，填写唯一账号名、密码及确认密码，即可进入自己的空工作区。账号名区分大小写。已注册的用户直接登录，不需要重新注册。每个账号仅管理自己的工作区；报名和签到分享链接仍无需登录。

原数据库继续存储原工作区，新账号数据库保存于 `DATABASE_PATH` 后附加 `.workspaces/` 的目录，例如 `data/morphos.db.workspaces/`。整机迁移请同时保留原数据库和整个旁置目录；单用户备份请使用工作区设置。目录已加入 Git 忽略。当前支持单个 Node 服务进程，不支持同工作区成员邀请或多进程同时注册。

恢复副本仍作为独立服务启动，不会把当前服务里其他人的工作区替换掉。部署隔离设计见 [ADR-0009](docs/decisions/ADR-0009-independent-workspaces.md)。
