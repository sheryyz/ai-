# MorphOS 需求规格（权威版 v1.0）

> 本文件是项目唯一权威需求。来源：`docs/spec/` 中的原始规格（另一模型起草）+ 本项目立项讨论中确定的五点修正。
> 若与 `docs/spec/`、`docs/archive/` 冲突，以本文件为准。
> 版本：v1.0 · 2026-11-11 · 省赛截止 2026-11-18

## 1. 一句话定义

**MorphOS 是一个意图驱动的通用轻量应用生成与演进平台。** 用户用自然语言获得一个真正能录入、保存、筛选、统计、导出数据的小应用；之后继续用自然语言提出新需求，应用在**保留全部业务数据**的前提下，经过**校验、预览、人工批准**持续演进，并可恢复到任一历史界面配置。

核心理念：**用户表达意图 → AI 编排应用 → 系统验证变更 → 用户确认 → 应用持续运行。**

## 2. 痛点（修正 1：从“搭建成本”具体化为“数据断裂”）

以一场 120 人的校园讲座为例，组织者在三个阶段要用四种工具：

| 阶段 | 常用工具 | 断裂点 |
|---|---|---|
| 筹备 | 问卷星收报名 | 导出 Excel |
| 整理 | Excel 管名单 | 手工去重、加列 |
| 现场 | 纸质表 / 小程序签到 | 签到结果与名单分离 |
| 跟进 | 微信群逐个提醒 | 要先人工找出谁没到 |

**每换一个阶段，数据就断一次。** 临时需求（“找出计算机专业还没签到的人，提醒他们”）没有任何一个工具能直接完成，只能手工拼表。实验室设备借用、社团物资管理有完全相同的结构。

MorphOS 的回答：**一套数据贯穿始终，工具随需求演进，而不是数据随工具迁移。**

## 3. 差异化（修正 2：对标真实竞品，而非“静态页面生成器”）

| 能力 | 飞书多维表格 / 简道云 / 明道云 AI | Google Stitch / 生成式 UI | A2UI / Tambo 等协议 | **MorphOS** |
|---|---|---|---|---|
| 自然语言生成首版应用 | ✅ | ✅（偏界面） | ✅（偏组件） | ✅ |
| 对**正在使用中**的应用做增量演进 | 部分，多为手动配置 | ❌ 多为重新生成 | ✅ 增量更新 | ✅ |
| 变更前展示影响并要求批准 | ❌ | ❌ | ❌ 协议层不负责 | ✅ Morph Diff |
| 组件间数据流有类型校验 | ❌ 手工关联 | ❌ | 部分 | ✅ Typed Ports |
| AI 错误输出自动校验并自修复 | ❌ | ❌ | ❌ | ✅ Validator-in-the-loop |
| 界面版本回滚且业务数据不受影响 | ❌ | ❌ | ❌ | ✅ |

**标准口径（答辩用）：** 别人解决“从 0 到 1 生成”，MorphOS 解决“从 1 到 N 演进”——对一个已经在用、已经有数据的应用，每一次 AI 修改都是**可解释、可验证、可撤销且不丢数据**的。

**诚实声明：** 声明式 UI、动态绑定、自然语言低代码均有成熟研究与产品，本作品不主张全球首创；差异化在于把“意图 → 受约束变更 → 校验 → 预览 → 批准 → 版本化”统一为一条可操作的流水线。

## 4. 目标用户与非目标

- **目标用户**：校园活动组织者、实验室管理员、社团负责人、小团队负责人等非专业开发者。
- **非目标**：支付结算、多租户商业系统、复杂 RBAC、实时协同编辑、任意第三方接口编排、AI 生成并执行任意代码。

## 5. 核心能力

| 编号 | 能力 | 说明 |
|---|---|---|
| C1 | Intent-to-App | 自然语言 → 数据模型 + 组件 + 绑定 + 操作，生成真实可用的应用 |
| C2 | Typed Binding | 组件声明类型化输入/输出端口，AI 生成绑定边，Validator 校验类型与无环 |
| C3 | Verified Morph Diff | 每个变更提案先经多层校验，再以语义差异展示新增 / 修改 / 保留 / 风险，批准后才生效 |
| C4 | Continuous Evolution | 增字段、加筛选、加组件、调布局；旧记录完整保留，新字段采用默认值 |
| C5 | Version Control | 每次批准生成配置版本；可恢复旧界面配置，**业务记录永不因配置回滚而改变** |
| C6 | Validator-in-the-loop | 模型输出不合法时，把结构化错误回馈模型自动修复（最多 2 轮），全过程对用户可见 |

## 6. 演示主线（必须全部真实可用）

### 场景 A：校园活动报名与签到（演进主线）
1. 应用中心输入：“创建一个校园讲座报名系统，包含姓名、学号、专业、手机号。”
2. AI 流式展示思考与分步进度，生成首版提案 → Morph Diff → 批准 → 应用可用。
3. 运行界面真实录入多条报名；刷新、重启服务后数据仍在；可编辑、搜索、导出 CSV。
4. 追加：“活动快开始了，加一个签到功能，找出计算机专业还没签到的人，给他们写提醒，旁边显示签到率。”
5. AI 生成增量 Patch（addField / addNode / bind / setFilter …）→ 校验 → Morph Diff 标明“复用已有报名数据、旧记录签到默认为否”。
6. 批准 → 界面变形 → 立即可签到；未签到名单、签到率、提醒草稿随签到实时联动。
7. **异常案例**：输入“把没签到的人从名单里删掉并重置数据”。协议中不存在删除业务数据的操作，Validator 拒绝并解释，建议“仅在视图中隐藏未签到人员”，改口后通过。
8. 恢复到旧版本界面：签到组件消失，**所有报名与签到数据不变**；再恢复到新版本，签到状态完整回来。

### 场景 B：实验室设备借用（通用性证明）
1. 新建应用：“设备借用管理：设备名称、编号、类别、状态（可借用/已借出/已归还）、借用人、借用日期。”
2. 同一引擎生成登记表单、设备列表、状态操作、分类统计；**不存在任何设备专用页面代码**。
3. 录入设备，执行借出 / 归还；可选追加“标出借出超过 7 天的设备”。

## 7. 功能范围与优先级（修正 5：进一步收缩）

| 级别 | 功能 | 验收 |
|---|---|---|
| P0 | 应用中心 | 列表、新建（自然语言 / 示例模板）、打开、重命名 |
| P0 | 字段类型 | string / text / number / date / boolean / enum，含必填与默认值 |
| P0 | 通用运行时 + 真实 CRUD | 新增、查询、编辑、单条删除（需用户在运行界面手动确认） |
| P0 | 筛选 DSL、统计、CSV 导出 | 结果来自真实记录；中文 CSV 不乱码 |
| P0 | AI 首版生成 + 增量 Patch | 调用真实模型；提案不直接生效 |
| P0 | Typed Ports + 分层 Validator | 结构 / 引用 / 类型 / 图 / 安全 / 版本六层 |
| P0 | Morph Diff + 版本历史 + 恢复 | 恢复只改配置不改数据 |
| P0 | AI 过程可视化（修正 3） | 流式思考摘要 + 分步进度（理解 → 规划 → 生成 → 校验 → 自修复 → 就绪） |
| P0 | 无 Key 降级 | 已有应用全部可用；固定样例明确标注“演示样例，非实时生成” |
| P0 | 自动化测试 | 单元 + 接口 + 1 条端到端 |
| P1 | 一条主动建议 | 例：签到率低于阈值时建议添加提醒组件，只建议不自动改 |
| P1 | 关系图视图 | 只读展示绑定图（React Flow） |
| 不做 | 每应用多实体 / addEntity | 省赛每个应用一个实体，协议保留扩展位 |
| 不做 | 删除字段、修改字段类型 | Validator 直接拒绝并说明“破坏性 Schema 变更不受支持” |
| 不做 | 拖拽反推意图、多租户、支付、真实短信微信 | 写入国赛规划；消息仅为草稿 + 复制 + 站内模拟记录 |

## 8. 研究生组评测（修正 4）

固定用例集：10 条创建类 + 10 条演进类 + 5 条非法 / 边界类。对比两种策略：

- **A 整体重生成**：每次把需求和当前应用交给模型，让它输出完整新 AppDefinition。
- **B 增量 Patch（本作品）**：只输出 Patch，由系统应用并校验。

指标：合法率、首轮通过率、自修复后通过率、数据保持率、无关修改数、非法操作阻断率、P50/P95 延迟、token 消耗。记录模型名、提示词版本、温度。**只写实际跑出的结果。**

## 9. 合规与真实性红线

1. **原创运行时**：允许使用 React、Tailwind、Radix、Framer Motion、React Flow 等通用库；**禁止**以 amis、Formily、Appsmith 等现成低代码引擎作为运行时核心。
2. **不伪造**：不伪造 Git 历史、Bug、测试结果、评测数据；未运行的测试不得声称通过。
3. **不伪装**：演示样例、模拟消息通道在界面上明确标注。
4. **密钥**：只经环境变量注入，`.env` 不入库；导出的 Prompt 记录在公开前须脱敏。

## 10. 成功判定

评委在同一平台从 0 生成两个不同的应用并真实保存数据；对其中一个提出新需求，看到流式思考、增量 Patch、Validator 与 Morph Diff，批准后立刻使用新功能；恢复旧版本后界面回退、数据完好；拔掉 API Key 后已有应用照常可用。
