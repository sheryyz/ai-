# ADR-0009：开放注册与独立工作区

日期：2026-11-17。用户明确要求每个人都能创建工作区管理员，覆盖此前不做多用户注册的范围约束。

- 每个账号管理一个独立工作区；账号名在当前服务中唯一，去首尾空格、区分大小写。一个工作区暂不支持邀请多名成员。
- 原 DATABASE_PATH 保持原位，原账号、数据、会话和分享链接保留。新工作区 SQLite 放在 `${DATABASE_PATH}.workspaces/`，采用服务端随机文件名；不从请求接受数据库路径。
- 各工作区沿用相同数据库结构，账号、会话、应用、记录、提案、版本、审计、分享令牌与备份均在自己的数据库中。服务端先按有效会话选择工作区，再调用原领域路由；分享入口按随机分享令牌定位数据库，不赋予管理权限。
- 尚未设置管理员的原工作区只能由本机首次设置；远程注册始终新建独立数据库，不能接管旧数据。
- 登录按账号名选择工作区；新增 `/api/auth/register`，既有 `/setup` 作为旧版首次设置兼容接口保留。注册保留密码长度、加盐哈希、同源写入保护与限流，禁止覆盖现有账号。
- 默认允许网络设备注册登录（ADMIN_ACCESS=any）；显式设置 local 时保留仅本机策略。公开网络部署使用 HTTPS。模型配置仍由部署者统一提供，注册用户共享模型配额，不支持各自配置 Key。
- 登录/退出时清空前端缓存，避免切换账号展示上一个工作区的数据。
- 备份只导出当前工作区；恢复仍生成独立副本，启动恢复副本会启动一份独立服务，不替换运行中的其他工作区。
- 当前部署模型为单个 Node 服务进程；工作区目录在启动时载入，新增注册立即加入当前进程。多进程注册协调、成员邀请、配额计费、邮件找回不在本轮范围。

验收：保留旧账号登录；新增两个账号；列表、ID 直访、记录、提案/批准、约束/阶段及备份隔离；分享仍按令牌可访问；密码变更只撤销本工作区会话；重启后账号数据可用；浏览器退出后可注册及切换账号。
