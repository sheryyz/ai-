## 1. 原始需求

用户原话：

> 现在还有什么没完成的吗，或者需要改进的吗，你可以再加上一个登录功能吗，界面风格和正文界面的风格要差不多，不会突兀的

助手提出单管理员与多用户注册两种范围，用户选择：

> 单管理员登录（推荐）：首次设置账号密码，登录后管理现有全部应用，手机分享页仍可直接访问

这一选择明确了应用归属不变，不需要把已有工作区改造成多租户系统。

## 2. 方案与实现（编者摘要）

- 首次本机设置管理员，不预设默认密码，不改已有业务记录。
- 密码加盐哈希；服务端会话令牌通过 HttpOnly Cookie 保存。
- 登录保护管理接口，手机分享接口继续按分享令牌处理。
- 登录界面复用 Logo、主题、卡片、输入框和按钮。
- 退出时撤销会话；会话过期后显示登录界面。

代码：`apps/server/src/auth.ts`、`apps/web/src/pages/LoginPage.tsx`、`apps/web/src/components/Shell.tsx`。

## 3. 开发中实际遇到的验证问题

### 类型检查失败

工具输出中出现过：

```text
error TS2532: Object is possibly 'undefined'.
error TS2305: Module '"./fixtures"' has no exported member 'Page'.
```

整理说明：前者来自测试读取 Cookie 响应头时没有处理缺失值；后者来自浏览器测试共享 fixture 没有转出所需类型。修正的是测试代码的类型边界与导出，不是删掉登录断言。

### 本地测试权限问题

一次未提升权限的接口测试出现：

```text
Error: listen EPERM: operation not permitted 127.0.0.1
```

这是执行环境不允许监听测试端口，不能写成应用业务故障。后续在允许本机测试端口的执行环境中重跑。

### 深色截图问题

助手原话：

> 界面沿用了平台原有样式。我在手机深色截图里发现输入框出现了不协调的浅色底，正在检查并修正。

后续检查发现截图截到了主题切换的过渡阶段；截图设置禁用动画后重新检查，稳定态输入框与暗色卡片一致。此处不应编写成“发现并修复了 CSS 配色算法 Bug”。

## 4. 实际验证与后续加强

本轮登录交付时报告的检查结果：共享逻辑 110 条、服务端 85 条、浏览器端到端 7 条通过。这是当时版本的计数，不是当前所有后续改动的总计数。

后续修改密码功能又补充了并发边界：密码修改期间正在执行的旧密码登录，哈希返回后须再次检查账号密码是否已变化，防止签发新会话。最终后续版本计数为共享逻辑 110 条、服务端 90 条。

测试代码：`apps/server/src/auth.test.ts`、`tests/e2e/auth.spec.ts`。测试账号属于测试库，未设置用户工作区的真实管理员账号。
